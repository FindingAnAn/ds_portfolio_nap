Business Context

Gold price is one of the most-watched financial signals — influencing investment decisions, hedging strategies, and macroeconomic analysis. The goal was to build a modular, production-ready forecasting system that integrates multiple data streams, engineers meaningful predictive signals entirely in SQL, and compares model families rigorously using time-aware validation.

Data Architecture — 3-Layer PostgreSQL

Data flows through three isolated schema layers to separate concerns and enable independent reprocessing:

RAWIngestyfinance, FRED, EIA APIs with source-level fallback
STAGINGCleanSchema enforcement, deduplication, outlier handling
FEATURESEngineer70+ window-function features in SQL
TRAINSplitTimeSeriesSplit CV, leakage-free scaler fit
PREDICTLogPrediction store + drift triggers

Automated ingestion adapters handle each source independently with source-level fallback for pipeline resilience. All features are computed using PostgreSQL window functions — no Python-side feature leakage.

Feature Engineering — 70+ Features, 8 Groups

Feature Groups
  • Financial price metrics (OHLCV returns)
  • Market trend signals (SMA, EMA, Bollinger)
  • Cross-asset relationships (USD, oil, equities)
  • Technical indicators (RSI, MACD, momentum)
Additional Groups
  • Macroeconomic signals (CPI, Fed rate, GDP)
  • Social sentiment proxies
  • Calendar / seasonality features
  • Lag features and rolling statistics

All features are computed entirely using SQL window functions in the features layer, making them reusable across model iterations and auditable without re-running Python code.

Model Training & Validation

Five model families were trained and compared across the Ridge-to-XGBoost spectrum:

Validation Strategy
  • TimeSeriesSplit cross-validation — no future data leakage
  • StandardScaler fitted only on training fold
  • Optuna hyperparameter search per model family
  • RMSE, MAE, R² tracked across all candidates
Model Monitoring
  • Best model persisted to prediction store
  • Prediction logging enables retrospective drift detection
  • Retraining triggers based on R² degradation
  • Model versioning with metadata (date, features, params)

Outcome & Learnings

Best modelXGBoost — R² 0.84, MAE ~18k VND
BaselineNaive persistence — R² 0.31
Key insightCross-asset features (USD, oil) dominate importance
Architecture3-layer PostgreSQL enables independent layer reprocessing

The project validated that SQL-native feature engineering with strict time-series CV prevents the leakage that often inflates performance in financial forecasting tasks. The modular architecture allows adding new data sources without touching downstream feature or model code.
